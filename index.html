PLAN2MODEL — evidence of the prototype

2D CAD drawings (DXF/DWG) → navigable 3D building model in the browser, glTF/OBJ files and a quantities table.
Public evidence page for an EIT Culture & Creativity funding application (acronym PLAN2MODEL), built 17 November 2026.

Everything on this page was produced by the prototype exactly as it exists in the repository: 269 automated tests pass; the four examples below were regenerated for this page The four example buildings shown here are synthetic drawings created with the prototype's own example tooling — they contain no client data. Open a viewer page: it runs entirely in your browser (the 3D library loads from a CDN, so the page needs an internet connection), with floor switching, layer toggles, view modes and downloads of the GLB model and the quantities CSV.

What the prototype does today

  • Reads DXF drawings (DWG via the free ODA converter) and classifies elements by their layer names against AIA, ISO 13567, BS 1192 and national conventions, with a fuzzy-match fallback (the repository's layer_mappings.yaml covers English, German, French, Spanish, Italian, Japanese, Portuguese, Arabic and Chinese patterns).
  • Detects floors and rooms, builds walls, slabs, doors, windows, columns, stairs and roofs as 3D geometry, and writes a self-contained viewer page, glTF/GLB/OBJ files and a quantities CSV.
  • Passes 269 automated tests (run 17 November 2026). Conversions of the examples below take seconds on an ordinary laptop.

Known limits (stated honestly)

  • Results depend on drawing-layer discipline; on real project drawings a share of elements stays unclassified and is shown as “unknown” in the statistics.
  • Doors and windows are drawn as separate boxes rather than cut into the walls.
  • The quantities file lists element counts and room areas; wall lengths and volumes are on the development plan.
  • No machine learning: classification is rule-based; learning from user corrections is a hypothesis to test, not a feature.

Files per example

Each example folder contains viewer.html (the 3D page), model.glb (the generated model), quantities.csv (element counts and room areas), parse_summary.txt (what the parser recognised, by element type), source.dxf (the synthetic input drawing) and screenshot.png where available.
